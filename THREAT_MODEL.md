# NEXORA threat model (vault)
**Protects against:** someone copying the database/backup file (entries are AES-256-GCM encrypted, each bound to its id; key derived from the master password with scrypt N=2^15,r=8,p=1 and a random salt); tampering with entries; offline guessing is slowed by the KDF.
**Does NOT protect against:** malware or a debugger running as you; a keylogger; screen capture while a password is revealed; a weak master password; someone using your unlocked session (use auto-lock); clipboard sniffers during the auto-clear window (default 20 s).
**Known limits:** KDF is scrypt, not Argon2id (Argon2id needs a native module; swap in later behind `vault.js`). Titles, URLs and workspace data are NOT encrypted (only vault entries). No OS key wrapping (DPAPI/safeStorage) yet. If the master password is lost, the vault cannot be recovered. Encrypted backups still require the master password of the time they were made. No independent security review has been done.

## v2 vault (MADAR, all platforms)
Format `madar-vault-v2`: PBKDF2-SHA256, 600,000 iterations, random 16-byte salt; AES-256-GCM per entry with the entry id as AAD (entries cannot be swapped). Key exists only in memory while unlocked (auto-lock; Ctrl+Shift+L). Imported backups cannot set hostile KDF parameters (iterations bounded).
Weaker than the desktop-only v1 vault in one respect: the key lives in the renderer (web page) process instead of the Electron main process, so a malicious script running in the page could reach it. The app ships a strict CSP and no third-party scripts.
Not protected: malware on the device, screen capture while a password is revealed, a weak master password, a stolen unlocked session. Clipboard auto-clear is best-effort. Scenes/backups of the 3D workspace are NOT encrypted (they hold only link titles/URLs and vault entry ids).
